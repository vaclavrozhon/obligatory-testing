\section{Auditing the main statements in Lean}
\label{sec:formalization}

The accompanying Lean~4 development~\cite{DeMouraUllrich2021} uses
mathlib~\cite{Mathlib2020} and is pinned to version~4.30.0.  This appendix is
organized as a reader-facing audit of the formal statements.  Each item first
states, in ordinary mathematical English, what one would like to verify and
points to its informal counterparts in \cref{sec:intro-obligatory-instance,sec:intro-blind,sec:intro-blind-optimization,sec:intro-revealing-optimization}.
It then displays the decisive part of a public Lean signature and explains
how to read it.

The excerpts suppress namespace prefixes, routine positivity hypotheses, and
local parameter definitions, but not the quantified input, algorithm,
completion premise, cost comparison, or error term.  The exact export name is
shown in every excerpt, so that the complete statement can be found by text
search in the accompanying source.  Randomized Lean statements represent
private randomness by a nonempty finite type of seeds and
\texttt{uniformAverage}; permutations, samples, and tie-breaking coins are
all included in such seeds.

\subsection{The common asymptotic meaning}

All competitive-ratio statements below use the following two predicates.

\begin{lstlisting}[style=lean]
def SizeAsymptoticUpper (alg opt : forall n, Family n -> Real)
    (c : Real) : Prop :=
  forall eps, 0 < eps -> exists N, forall n, N <= n ->
    forall I, alg n I <= (c + eps) * opt n I

def FixedSizeLowerBound (cap : Cap) (ratio : Real) : Prop :=
  forall strategies : forall n, Online.Strategy n,
    forall eps, 0 < eps -> forall N,
      exists n, N <= n /\
        exists I : FixedInput cap n, exists fuel,
          I.defeats (strategies n) fuel (ratio - eps)
\end{lstlisting}

Here \texttt{I.defeats} means that the finite run has settled and either
leaves a job incomplete or satisfies
\((R-\eps)\OPT(I)\le\ALG(I)\).  Thus the two predicates are exactly the
upper and lower quantifier orders used for the size-asymptotic ratios in the
paper; in particular, the lower input is fixed after the algorithm has been
chosen.

\subsection{Obligatory testing: exact competitive ratios}

\begin{theorem}[Lean-audited obligatory-testing ratios]
\label{thm:lean-audit-obligatory-ratios}
Let $z_*>1$ be the unique solution of $z_*-3=\ln z_*$ and put
\[
 R_*=1+\frac{2}{z_*-1}=1.570574\ldots.
\]
In obligatory testing, the optimal deterministic size-asymptotic
competitive ratio is $R_*$.  Against an oblivious adversary, the optimal
randomized ratio is $4/3$.  This is the formal counterpart of
\cref{thm:intro-obligatory}.
\end{theorem}

For the deterministic statement, the public record contains both directions
and an actual completing online strategy.

\begin{lstlisting}[style=lean]
structure ObligatoryExactRatioConclusion (ratio : Real) : Prop where
  lower : LowerBound.FixedSizeLowerBound .infinite ratio
  upper :
    exists strategy : forall n, Online.Strategy n,
      UpperBound.CompletesByAnalysisFuel .infinite strategy /\
      SizeAsymptoticUpper
        (UpperBound.strategyCost .infinite strategy)
        (UpperBound.fixedOfflineCost .infinite) ratio

theorem exact_ratio_main :
    (forall {u : Real}, 0 < u ->
      FiniteExactRatioConclusion u (exactCurve u)) /\
    ObligatoryExactRatioConclusion RStar
\end{lstlisting}

The definitions in \path{SchedulingPaper/Constants.lean} identify
\texttt{RStar} with $R_*$, while the second conjunct supplies the matching
lower and upper bounds.  The completion field rules out a certificate that
only analyzes a partial transcript.

For the randomized statement, Lean exposes a finite upper error and a fixed
binary input for the lower bound.

\begin{lstlisting}[style=lean]
theorem unknownMultiset_operational_expectedCost_le_20378
    ... (p : Fin (k + rest) -> Real) (hp : forall i, 0 <= p i) :
    uniformAverage
        (physicalSampledRunCost (k + rest) k d eta h_eta p) <=
      4 / 3 * finiteObligatoryOPT p + 20378 * R ^ 7

theorem oblivious_iid_binary_lower_online_actualOPT
    {n : Nat} (hn : 0 < n)
    (strategy : Seeds -> Online.Strategy n) (fuel : Nat)
    (hdone : forall seed input job, ... = .done) :
    exists input : BinaryInput n,
      (4 * n / (3 * n + 5)) *
          finiteObligatoryOPT (iidBinaryProcessingTime input) <=
        uniformAverage fun seed =>
          Online.runCompletionCost .infinite ...
\end{lstlisting}

The upper theorem uses the literal fixed-cutoff sample--learn--fallback
algorithm $\mathcal A_n^{(32)}$ from
\cref{thm:rand-obligatory}, with $d=\lfloor n^{1/4}\rfloor$,
$k=\lfloor n^{3/4}\rfloor$, and cutoff $32$.  With this checked parameter
choice, $R^7=o(n^2)$.  Thus Lean verifies the exact competitive ratio.  This
is the fixed-cutoff branch now displayed explicitly in
\cref{alg:intro-obligatory-rand}, not its growing-cutoff companion.  In the
lower theorem the selected
$\{0,2\}$ input is outside the seed average, and $4n/(3n+5)\to4/3$.

\subsection{Obligatory-testing instance optimality}

\begin{theorem}[Lean-audited obligatory instance comparison]
\label{thm:lean-audit-obligatory-instance}
Fix $L<\infty$.  There is one randomized nonanticipating algorithm, whose
parameters depend on $n$ but not on the input or on $L$, such that for every
$p\in[0,L]^n$ and every completing announced algorithm $\mathcal B$ with a
finite private seed,
\[
 \EE\ALG_{\mathcal A^*}(p)
 \le \EE\ALG_{\mathcal B}(p)+o_L(n^2).
\]
The assignment of the entries of $p$ to public labels is hidden by a private
uniform permutation.  This is the finite-seed version of
\cref{thm:intro-obligatory-instance}.
\end{theorem}

The final Lean comparison is already between the physical learned run and an
arbitrary family of completing competitors.

\begin{lstlisting}[style=lean]
theorem exists_fixedPlacement_universalGrowingPolicy_concrete_rate
    {Seeds : Type*} [Fintype Seeds] [Nonempty Seeds]
    ... {L : Real} (hL : 0 < L)
    (p : Fin (k + r) -> Real)
    (hp0 : forall job, 0 <= p job)
    (hpL : forall job, p job <= L)
    (competitor : Seeds -> CompletePolicy p)
    (htest : forall seed, FirstTouchesAreTests (competitor seed)) :
    exists placement,
      uniformAverage (physicalGrowingRunCost ... p) <=
        (k + r : Real) ^ 2 *
          (uniformAverage (fun seed =>
             normalizedCost p (competitor seed) placement) +
           2 * concreteUniversalGrowingError L n)

theorem concreteUniversalGrowingError_tendsto_zero (L : Real) :
  Tendsto (concreteUniversalGrowingError L) atTop (nhds 0)
\end{lstlisting}

\texttt{FirstTouchesAreTests} is exactly the obligatory-testing restriction.
The conclusion chooses one hidden placement before averaging over the
competitor's seed, while the learned algorithm averages over its own private
sample and order.  The second theorem turns the displayed normalized error
into $o_L(1)$.

The checked universal growing-cutoff family is structurally the same
sample--learn--fallback algorithm but uses a deliberately slower convenient
parameter sequence: if $m=\lfloor n^{1/32}\rfloor$, it has cutoff $m-1$,
$m^2-1$ positive grid intervals, mesh $1/m$, and pilot size of order
$n^{7/8}$.  The development does not currently identify this literal family
with the fixed-cutoff family used above or prove the uniform unbounded
$4/3$ estimate for this growing family.  The manuscript separately proves its
sharper $n^{3/4}$-pilot, $32+n^{1/20}$-cutoff version.  Hence the exact ratio
and the bounded instance comparison are both checked, but their realization
by one definitionally identical Lean strategy is not part of the audit.

\subsection{Why the obligatory instance assumptions are necessary}

Lean also checks both limitations stated after
\cref{thm:intro-obligatory-instance}.  Every completing deterministic policy
has a fixed balanced zero--two input on which its literal cost is at least
$9n^2/8$.  Without a fixed input bound, every finite-seed randomized policy
has a fixed input in $[0,n^2]^n$ on which it loses at least $n^2/8$ against
the corresponding announced comparison schedule.

\begin{lstlisting}[style=lean]
theorem deterministic_balanced_cost_lower
    (m : Nat) (strategy : Strategy (2 * m)) (fuel : Nat)
    (hcomplete : forall processing, ... -> CompletesAll processing strategy fuel) :
    exists processing,
      (forall job, processing job = 0 \/ processing job = 2) /\
      (Finset.univ.filter fun job => processing job = 2).card = m /\
      9 * ((2 * m : Nat) : Real) ^ 2 / 8 <=
        runCompletionCost .infinite processing ...

theorem finiteSeed_exists_operational_quadratic_gap
    {n : Nat} (hn : 7 <= n)
    (strategy : Seeds -> Strategy n) (fuel : Nat)
    (hdoneHigh : ...) (hdoneZero : ...) :
    n ^ 2 / 8 <= averageCostOnAllHigh - announcedAllHighCost \/
      exists label,
        n ^ 2 / 8 < averageCostWithOneZero label - announcedOneZeroUpper
\end{lstlisting}

The first input is frozen after the deterministic strategy is fixed.  In the
second theorem the exceptional zero label, when that branch is selected, is
outside the private-seed average.  These are the two operational quantifier
orders required by \cref{thm:ot-instance-impossibility}.

\subsection{Blind execution}

\begin{theorem}[Lean-audited blind-execution statements]
\label{thm:lean-audit-blind-execution}
For every fixed $L<\infty$, one randomized nonanticipating algorithm is
instance-optimal on every $p\in[0,L]^n$ up to $o_L(n^2)$, even against an
announced completing competitor.  If no common upper bound on processing
times is imposed, no randomized algorithm has a finite asymptotic
competitive ratio.  The bounded statement is
\cref{thm:intro-blind-instance}; the preceding paragraph in
\cref{sec:intro-blind} states the unbounded limitation.
\end{theorem}

The bounded comparison is a direct per-input inequality.

\begin{lstlisting}[style=lean]
theorem boundedUniform_blindPilot_concrete_rate
    {n : Nat} ... {L : Real} (hL : 0 < L)
    (p : Fin n -> Real)
    (hp0 : forall job, 0 <= p job)
    (hpL : forall job, p job <= L)
    (competitor : CompletePolicy p) :
    uniformAverage (fun pilotOrder =>
      uniformAverage (blindPilotLearnedCost G pilot pilotOrder)) /
        (n : Real) ^ 2 <=
      uniformAverage (normalizedCost p competitor) +
        7830 * (L + 1) ^ 2 / concreteUnknownParameter n
\end{lstlisting}

The left side is the learned four-block algorithm; the right side is the
private-shuffle cost of an arbitrary announced competitor.  The checked
parameter tends to infinity, so the last term tends to zero.  The finite-seed
corollary
\path{boundedUniform_blindPilot_finiteSeed_concrete_rate}
performs the pointwise conditioning and averaging in Lean itself.

For the unbounded part, Lean states the contradiction entirely in terms of
literal completion costs.

\begin{lstlisting}[style=lean]
theorem no_finite_ratio_at_quadratic_scale_operational
    {n : Nat} (hn : 0 < n)
    (strategy : Seeds -> Strategy n)
    (hcomplete : forall seed, CompletesAllNonnegative (strategy seed))
    (R eta : Real) ...
    (hzeroCost : average zeroCost <= eta * n ^ 2)
    (hcompetitive : forall label,
      average (oneLongCost (n ^ 2) label) <=
        R * n ^ 2 + eta * n ^ 2) : False
\end{lstlisting}

Thus a low cost on the all-zero input and an $R$-competitive cost on every
input with one length-$n^2$ job cannot hold simultaneously for large $n$.

\subsection{Blind optimization: the two worst-case curves}

\begin{theorem}[Lean-audited blind-optimization curves]
\label{thm:lean-audit-blind-optimization-curves}
For every fixed $u>0$, the exact deterministic ratio is
\[
 \RdetBO(u)=
 \begin{cases}
  1,&u\le1,\\
  u,&1\le u\le2,\\
  \dfrac{\sqrt{4u^3-4u+1}-1}{2(u-1)},&u\ge2,
 \end{cases}
\]
and the exact randomized ratio is
\[
 \RrandBO(u)=
 \begin{cases}
  1,&u\le1,\\
  \dfrac{u^3}{u^2+(u-1)^3},&1\le u\le u_{\mathsf{BO}},\\
  \dfrac12\left(1+\sqrt{\dfrac{u^2+u-1}{u-1}}\right),
     &u\ge u_{\mathsf{BO}},
 \end{cases}
\]
where $u_{\mathsf{BO}}>1$ is the unique root of
$u^3-2u^2-u+1=0$.  This expands the two curves summarized in
\cref{thm:intro-bo-det-curve}.
\end{theorem}

The Lean definitions contain these formulas literally.

\begin{lstlisting}[style=lean]
def deterministicCurve (u : Real) : Real :=
  if u <= 1 then 1
  else if u <= 2 then u
  else (sqrt (4 * u ^ 3 - 4 * u + 1) - 1) / (2 * (u - 1))

def randomizedCurve (u : Real) : Real :=
  if u <= 1 then 1
  else if u <= randomizedTransition then
    u ^ 3 / (u ^ 2 + (u - 1) ^ 3)
  else
    (1 + sqrt ((u ^ 2 + u - 1) / (u - 1))) / 2
\end{lstlisting}

For the deterministic curve, one exported theorem gives both a completing
upper strategy and a fixed input against every completing strategy, with
linear remainders.

\begin{lstlisting}[style=lean]
theorem deterministicCurve_operational_exact (hu : 0 < u) :
  (exists strategy : forall n, Online.Strategy n,
    (forall n, Online.CompletesAll u (strategy n)) /\
    forall n processing, admissible u processing ->
      runCost u processing (strategy n) n <=
        deterministicCurve u * offlineCost u processing +
          (1 + u) * n / 2) /\
  (forall n, 0 < n -> forall strategy,
    Online.CompletesAll u strategy ->
    exists processing, admissible u processing /\
      runCost u processing strategy n >=
        deterministicCurve u * offlineCost u processing -
          (2 * u ^ 2 + u) * n)
\end{lstlisting}

For randomization, the literal pilot algorithm supplies the upper direction,
and finite Yao selects a fixed binary input for the lower direction.

\begin{lstlisting}[style=lean]
theorem operationalPilot_expectedCost_le_curve_normalized ... :
  uniformAverage (fun sampleOrder =>
    conditionalExpectedPilotRunCost ... sampleOrder) <=
      randomizedCurve u * offlineCost u processing +
        pilotNormalizedError u n pilotSize * n ^ 2

theorem exists_binary_mass_operational_ratio_tendsto_curve (hu : 1 < u) :
  exists b in Set.Icc (0 : Real) 1,
    Tendsto (fun n => binaryFiniteYaoRatio n u b)
      atTop (nhds (randomizedCurve u)) /\
    forall n Seeds, 0 < n -> forall strategy : Seeds -> Strategy n,
      (forall seed, CompletesAll u (strategy seed)) ->
      exists input : BinaryInput n,
        binaryFiniteYaoRatio n u b * offlineCost u input <=
          uniformAverage fun seed => runCost u input (strategy seed) n
\end{lstlisting}

The theorem \texttt{pilotNormalizedError\_tendsto\_zero} verifies that any
growing sublinear pilot makes the upper error vanish.

\subsection{Blind-optimization instance optimality}

\begin{theorem}[Blind-optimization instance statement]
\label{thm:lean-audit-blind-optimization-instance}
For fixed $u<\infty$, a sample-then-commit randomized algorithm satisfies,
for every $p\in[0,u]^n$,
\[
 \EE\ALG_{\mathcal A^*}(p)
 \le \frac{n(n+1)}2\min\{u,1+\mu_p\}+o_u(n^2),
 \qquad \mu_p=\frac1n\sum_i p_i.
\]
Conversely, every completing algorithm with a finite private seed has
expected cost at least
\[
 \frac{n^2}{2}\min\{u,1+\mu_p\}-nu\sqrt{2n}.
\]
Hence both sides have the same leading value and Lean verifies the full
instance-optimal comparison in \cref{thm:intro-bo-instance}.
\end{theorem}

Lean checks both the operational sample-then-commit construction and the
arbitrary-policy lower benchmark:

\begin{lstlisting}[style=lean]
theorem conditionalExpectedPilotRunCost_eq ... :
  conditionalExpectedPilotRunCost ... = conditionalExpectedPilotCost ...

theorem pilotPolicy_expectedCost_le ... :
  uniformAverage (fun sampleOrder =>
    conditionalExpectedPilotCost ... sampleOrder) <=
      n * (n + 1) / 2 * min u (1 + populationMean processing) +
      (1 + u) * pilotSize * n +
      n * (n + 1) / 2 * (u / sqrt pilotSize)

theorem finiteSeed_expectedCost_ge_instanceBenchmark_nsq
    {Seeds : Type*} [Fintype Seeds] [Nonempty Seeds]
    ... (p : Fin n -> Real)
    (hp : forall job, p job in Set.Icc 0 u)
    (strategy : Seeds -> Online.Strategy n)
    (hcompletes : forall seed placement,
      Online.Completes (placedProcessing p placement) (strategy seed)) :
    n ^ 2 / 2 * min u (1 + populationMean p) -
        n * u * sqrt (2 * n) <=
      uniformAverage fun seed =>
        uniformAverage fun placement =>
          Online.runCost u (placedProcessing p placement)
            (strategy seed) n

theorem instanceBenchmark_normalizedError_tendsto_zero (u : Real) :
  Tendsto (fun n : Nat => u * sqrt (2 / (n : Real))) atTop (nhds 0)
\end{lstlisting}

The upper errors are $o_u(n^2)$ for any growing sublinear pilot.  The lower
error is explicit; the third export proves that after division by $n^2$ it is
$u\sqrt{2/n}=o_u(1)$.  Its proof compiles a literal completing online
strategy into a causal first-touch trace, applies a uniform-permutation
first-moment bound at every position, and averages directly over the
algorithm's private seed.  Thus no conditioning step is left to prose.

\subsection{Revealing optimization: exact competitive-ratio curves}

\begin{theorem}[Lean-audited revealing-optimization curves]
\label{thm:lean-audit-revealing-curves}
For every $u>0$, the deterministic ratio is the six-piece function
$\RdetRO(u)$ displayed in \cref{eq:opt:full-curve}.  The randomized ratio is
\[
 \RrandRO(u)=
 \begin{cases}
  1,&0<u\le1,\\
  \dfrac{u^3}{u^2+(u-1)^3},&1\le u\le u_2,\\
  1+\dfrac1{2(\sqrt u-1)},&u_2\le u\le25/4,\\
  4/3,&u\ge25/4,
 \end{cases}
\]
where $u_2>1$ is the unique root of
$u^3-6u^2+5u-1=0$.  These are the curves summarized in
\cref{thm:intro-common-upper-curves}.
\end{theorem}

The deterministic curve is the first conjunct of the same top-level theorem
used for the obligatory endpoint:

\begin{lstlisting}[style=lean]
theorem exact_ratio_main :
  (forall {u : Real}, 0 < u ->
    FiniteExactRatioConclusion u (exactCurve u)) /\
  ObligatoryExactRatioConclusion RStar

def exactCurve (u : Real) : Real :=
  if u <= 1 then 1
  else if u <= uDiamond then u
  else if u <= uZero then rhoI u
  else if u <= goldenRatio + 2 then reciprocalBranch u
  else if u <= zStar then mixedFiniteCurve u
  else RStar
\end{lstlisting}

Here \texttt{FiniteExactRatioConclusion} has the same lower field,
completing strategy, and \texttt{SizeAsymptoticUpper} field displayed at the
start of this appendix.  The branch functions and all five joins are proved
in \path{SchedulingPaper/ExactCurve.lean}.

For the randomized curve, the scalar definition and the two attaining binary
families are explicit:

\begin{lstlisting}[style=lean]
def randomizedCurve (u : Real) : Real :=
  if u <= 1 then 1
  else if u <= transition then boundaryRatio u
  else if u <= 25 / 4 then interiorRatio u
  else 4 / 3

theorem binaryFamilies_le_curve (hu : 1 < u) :
  (forall tau, 1 <= tau -> tau <= u ->
     familyB u tau <= randomizedCurve u) /\
  (forall tau, 1 <= tau -> tau <= u - 1 ->
     familyA tau <= randomizedCurve u)

theorem binaryFamilies_attain_curve (hu : 1 < u) :
  (exists tau in Set.Icc 1 u,
     familyB u tau = randomizedCurve u) \/
  (exists tau in Set.Icc 1 (u - 1),
     familyA tau = randomizedCurve u)
\end{lstlisting}

The operational Yao theorem
\path{exists_operational_binary_family_ratio_tendsto_curve} then
selects one fixed labeled binary input outside every finite seed average.
The theorem \path{randomizedRevealingCurveExact} is one public package
containing this lower theorem, the announced operational upper theorem, the
checked announced-to-unannounced transfer, and vanishing of the transfer
error.  The transfer itself is exported as
\path{compiledExpectedNormalizedCost_le_curve_of_competitor}: given a
finite-seed announced policy satisfying the curve bound on every placement,
it returns the corresponding direct bound for the literal unannounced pilot
learner.

\subsection{Revealing-optimization instance optimality}

\begin{theorem}[Lean-audited revealing instance comparison]
\label{thm:lean-audit-revealing-instance}
Fix $u<\infty$.  There is one randomized nonanticipating algorithm such that
for every $p\in[0,u]^n$ and every completing announced algorithm
$\mathcal B$ with a finite private seed,
\[
 \EE\ALG_{\mathcal A^*}(p)
 \le \EE\ALG_{\mathcal B}(p)+o_u(n^2).
\]
This is the finite-seed version of
\cref{thm:intro-common-upper-instance}.
\end{theorem}

The final public theorem compares the literal learned strategy directly with
the arbitrary competitor on one hidden placement.

\begin{lstlisting}[style=lean]
theorem exists_fixedPlacement_compiled_le_randomizedCompetitor_concrete_rate
    {Seeds : Type*} [Fintype Seeds] [Nonempty Seeds]
    ... {u : Real} (hu : 0 < u)
    (p : Fin n -> Real)
    (hp0 : forall job, 0 <= p job)
    (hpu : forall job, p job <= u)
    (competitor : Seeds -> CompletePolicy p) :
    exists placement,
      compiledExpectedNormalizedCost grid pilot u <=
        (uniformAverage fun seed =>
          normalizedRawCost u p (competitor seed) placement) +
        concreteRevealingComparisonError u n

theorem concreteRevealingComparisonError_tendsto_zero (u : Real) :
  Tendsto (concreteRevealingComparisonError u) atTop (nhds 0)
\end{lstlisting}

The left side is an actual fixed-fuel transcript-only strategy averaged over
independent pilot and main permutations.  The competitor may adapt among
tests, processing, and raw execution and is given the input multiset.  The
placement is chosen before its seed is averaged, and the second theorem
supplies the required $o_u(1)$ normalized error.

The concrete checked pilot has size
$\lfloor n/m^2\rfloor=\Theta(n^{7/8})$, where
$m=\lfloor n^{1/16}\rfloor$.  This is now the parameter choice displayed in
the introductory pseudocode as well.

\subsection{Proof boundary and reproduction}

The root module \path{SchedulingPaper.lean} imports the developments used by
all exports above.  The checked project contains no \texttt{sorry},
\texttt{admit}, or project-defined \texttt{axiom}.  It uses mathlib's
classical real analysis and noncomputable choices of exact real parameters;
it proves mathematical properties of the algorithms but does not extract a
floating-point implementation.  The randomized lower statements shown here
quantify over nonempty finite seed types.

All mathematical directions of the Section~1 headline theorems now have
Lean exports.  The checked obligatory $4/3$ and
bounded instance-optimal upper bounds currently use different concrete
parameter families, as recorded above.  Lean verifies the exact symbolic
constants, branch transition equations, and the rational decimal brackets
listed above.  Longer printed digit strings remain readability aids unless a
correspondingly narrow interval is explicitly exported.

From the repository root, the complete development is checked with
\begin{center}
\texttt{lake build}
\end{center}
and each displayed export can be located by searching for its theorem name.
