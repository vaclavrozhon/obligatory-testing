\section{Machine-checked verification}
\label{sec:formalization}

The accompanying Lean~4 development~\cite{DeMouraUllrich2021} uses
mathlib~\cite{Mathlib2020} and is pinned to version~4.30.0.  Its root module
imports every development listed below.  The following table states the proof boundary;
\cref{app:lean-formalization} gives the detailed paper--Lean dictionary for
the deterministic theorem.

In the table, \emph{operational} or \emph{literal} means that Lean models the
schedule action by action, while a \emph{transcript-only} strategy chooses
each next action only from the public transcript.  \emph{End-to-end} means
that the cited export starts from such a strategy or execution and reaches
the stated cost bound, rather than checking only an intermediate algebraic
identity.  A \emph{certificate} is a proved inequality used by that
end-to-end argument.  A \emph{diagonal correction} is the linear contribution
of the terms with the same job in both positions of a double sum; we call it
a one-job correction in the prose below.  Finally, \emph{fuel} is a finite
upper bound on the number of internal action-selection steps used to run the
formal strategy.

The development contains no \texttt{sorry}, \texttt{admit}, or
project-defined axiom.  Formal randomized statements use finite uniform
averages for private seeds and explicit nonnegative finite weights for Yao
input laws; these cover permutations, sample choices, tie-breaking coins,
and the exact Bernoulli masses used here.  Classical real analysis and
noncomputable exact minimizers occur only in certificates; no floating-point
program is extracted.
